# AI Vendor Developer/Accessibility Forms - Barrier and Gap Audit (2026-11-22)

## Systematic review of all five vendors public developer/support/accessibility contact channels for disability barrier availability

## Method: Direct capture of each vendor developer-form / contact / accessibility page URL. Each page searched for key terms.

## Key Findings

1. **Google** is the only vendor with a dedicated public Accessibility Help Center (support.google.com/accessibility), ASL-specialist contact, and a cognitive/learning resources page - all captured. But: **no Google Gemini AI product has a dedicated AI-specific disability-access channel.** The Gemini help page is 1.5MB of CSS shells with zero substantive disability content.

2. **OpenAI** has zero accessibility-specific pages. The contact page (286KB) contains no accessibility/disability content. The developer forum is community-run, not a formal ADA-access channel. The API docs contact page returns 404. 8 pages captured, ZERO accessibility content.

3. **Anthropic** has zero accessibility-specific pages. The contact page 404s and the safety page (200, 204KB) has no accommodation or disability language. No accommodation-request pipeline. No human escalation path for AI-related cognitive-access failures.

4. **Meta**: Help pages return HTTP 400 (bot-walled). The Quest support page shows the AI-assistant-only escalation pattern documented in the Nov 11 support chat. No accessibility channel, no ADA contact, no developer-form barrier-reporting pipeline.

5. **xAI/Grok**: No accessibility or disability content on any public page. X ToS and Privacy Policy mention "accessibility" twice as CSS boilerplate. Grok contact page bot-walled (403). No accessibility channel at all.

6. **The gold mine**: every vendor lacks: (a) a documented ADA accessibility-contact certification, (b) an individualized-accommodation request pipeline, (c) a runtime barrier-reporting mechanism, (d) a Section 5 accessibility-contact person per 47 CFR 14.31, (e) an emergency escalation path for users with cognitive disabilities, (f) any commitment to accessibility for the AI itself (as opposed to traditional web accessibility).

## This is the evidence pattern: every vendor with a deployed AI system has no runtime accessibility-contact certification. That is the gap the FCC RDA fills.
